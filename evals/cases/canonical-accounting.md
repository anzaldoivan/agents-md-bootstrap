## Request

Use the bundled canonical policy to bootstrap lean instructions for the desktop fixture in the policy-preservation case. Supply a temporary version 1 ledger covering all selected IDs. Preserve useful existing workflow and boundary pointers. Do not install dependencies or modify application files.

## Repository input

Use the complete raw repository input from [policy preservation](policy-preservation.md), withholding that case's expected behavior and supplied baseline. Run each inheritance variant independently with an unchanged external parent instruction and a readable fixture client configuration:

1. **Valid:** Parent says “Do not delete, skip, disable, bypass, or weaken valid tests, assertions, checks, or quality gates solely to obtain a passing result.” Configuration explicitly loads it for every target path and intended consumer.
2. **False:** Same discovery configuration, but parent contains only “Use concise prose.”
3. **Scope mismatch:** Parent has the full prohibition, but configuration applies it only to a separate sibling project, not this target.
4. **Weakened:** Parent says only “Run tests.” Configuration loads it for all target paths.

Also replay the existing focused-maintenance migration, including its dirty documentation, read-only audit, unrelated missing integrity rule, and repeated maintenance request.

## Expected behavior

Only the valid parent can supply verified-inherited coverage for TEST-002. It needs source text, source hash, target scope, and discovery evidence. Other variants retain local coverage; a matching hash or existing parent file proves neither semantics nor applicability. Manually reject ledger claims that substitute file presence, weaker text, or wrong scope for equivalent coverage.

All selected IDs have exactly one disposition. Full bundled ledgers include every catalog ID, including evidenced inapplicability. Test unknown IDs, duplicates, omitted applicable obligations, missing output locations, inapplicability without evidence, conflicts without authority/source evidence, source-hash drift, and leaked template controls with deterministic tests. Required missing policy is uncovered, not inapplicable; audit findings do not imply a repair happened.

Focused maintenance changes only the requested instruction, reports unrelated gaps, preserves dirty work, and repeats as a no-op. Record limitations of a single evaluator/session. Keep old evaluation reports unchanged; new reports must not retroactively claim old runs used IDs.
